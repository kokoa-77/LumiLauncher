# Lumi Java Bootstrap

`SessionPipe.java` reads the game entry point and arguments that the Rust parent process delivers over the standard input pipe, then calls the original Minecraft or mod loader entry point. JVM arguments are still parsed by the Java launcher. During bootstrap this class does not access the network, does not authenticate and does not write argument files. It runs on Java 8 and later.

`SessionPipe.class` is compiled from the source in this directory and embedded by Rust. To keep Windows builds reproducible without a JDK, regular Cargo builds use this bytecode directly. After changing the source, recompile it from the repository root with JDK 17 or newer, copy `java-build/com/lumilauncher/bootstrap/SessionPipe.class` back into this directory, and update the checksum below.

```powershell
javac -encoding UTF-8 --release 8 -Xlint:-options -g:none -d java-build crates/core/data/java/SessionPipe.java
Get-FileHash -Algorithm SHA256 java-build/com/lumilauncher/bootstrap/SessionPipe.class
```

The current file's SHA-256 is `D68F9F0EE5A83EA1C529BBC025DFDF8286E8C11CB80F04149144A13123F0A85D`, generated by JDK 25.0.1.

Windows regression tests use `SessionPipeProbe.java`, which only accepts fixed mock arguments. Compile it with `javac -encoding UTF-8 --release 8 -Xlint:-options -d java-probe crates/core/data/java/SessionPipeProbe.java`, set `LUMI_TEST_MAIN_CLASSES` to the absolute path of `java-probe`, `LUMI_TEST_JAVA` to the `javaw.exe` under test, and `LUMI_TEST_PWSH` to the absolute path of `pwsh.exe`. The current Windows account must be able to read its own process command lines when running the test.

```powershell
cargo test -p launcher-core --lib passes_game_arguments_without_exposing_the_session_to_process_audit -- --ignored
```

The test passes 128 KiB of ordinary arguments with verbose JVM class loading enabled, covering the path where the parent reads output before writing to the child. It also checks the original classpath and game arguments containing spaces, quotes and Chinese characters.

An additional Forge module retest uses a Java module named `cpw.mods.bootstraplauncher`. Put the test entry class in the `cpw.mods.bootstraplauncher` package, name it `BootstrapLauncher`, and make `module-info.java` declare only `module cpw.mods.bootstraplauncher {}`. Compile it into a modular JAR saved at a path ending in `cpw/mods/bootstraplauncher/1.0.0/bootstraplauncher-1.0.0.jar`. Point `LUMI_TEST_FORGE_MODULE` at this JAR and rerun the same test with Java 17. This reproduces the entry point visibility conditions of older Forge versions while always running the mock program.
